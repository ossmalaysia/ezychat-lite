# Template list publisher (proposal for anchorsprint/ezychat-connectors)

Everything in this folder is a **proposal** for the public publishing repo; nothing here runs in the app. The app side
(download, checks, gallery) is in `packages/server/src/templates/` and `apps/web/src/admin/`. Design:
`../design.md`.

## Folder format (`templates/` in the publishing repo)

```
templates/
  categories.json                 [{ "id": "health", "name": { "en": "…", "ms": "…", "zh-CN": "…" } }, …]
  <id>/
    template.json                 id, version, schemaVersion, minAppVersion, editions, category, icon,
                                  preset, defaults?, recommendedConnectors?,
                                  texts: { en: { agentName, name, description, keywords, contextName }, ms?, zh-CN? }
    en/focus.md                   business part of the role (the app puts the agent type's starting text first)
    en/handoff-rules.md           one rule per line
    en/context.md                 the Business context item: blank fill-in lines ("Opening hours:")
    ms/…  zh-CN/…                 optional; a missing language uses the whole English set
```

Long texts are plain Markdown files so a reviewer reads them as text, not as escaped JSON strings.

Rules for authors (from `docs/LEARNINGS.md` of ezychat-lite):

- Context items use blank fill-in lines, never sample values or `[your price]` placeholders: the AI repeats a
  placeholder as a fact but hands over on a blank line.
- No tool names in the texts (tools describe themselves); a sheet tab keeps its real name in every language.
- `icon` is a name from the app's bundled set (`TEMPLATE_ICONS` in `apps/web/src/admin/business-templates.ts`); an
  unknown name shows a neutral icon until an app release adds it.
- Raise `version` to replace a template the app ships (the app's own are version 1); a new `id` adds a template.
- Keep `minAppVersion` at the first app version that understands every field you use.

## Files here

| File                  | Purpose                                                                                                                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `templates/`          | Today's 18 app templates in this format, generated by `npm run templates:export` in ezychat-lite (the test `scripts/template-store.test.mjs` keeps it equal to the app). Copy it as the repo's first `templates/`. |
| `build-templates.mjs` | Assembles, validates (JSON Schema with ajv 8 + cross checks: folder = id, unique ids, known category, English required, complete language folders), writes `templates-v1.json`, signs it.                          |
| `templates.yml`       | Workflow proposal: validate on every PR, build + sign + upload on `main`.                                                                                                                                          |

The JSON Schema is generated in ezychat-lite: `npx tsx scripts/template-schema.mjs > schema/template-v1.json`.

## Signing

- Same Ed25519 key pair as the connector list (secret in the protected `release` environment). The app trusts the
  same two public keys (`CONNECTOR_LIST_PUBLIC_KEYS`), so key rotation works the same way for both lists.
- The signature covers `ezychat-templates-v1\n` followed by the exact bytes of `templates-v1.json` (domain
  separation: a connector list signature never verifies as a template list and the other way round).
- `TEMPLATE_LIST_SIGNING_KEY` takes the private key as PKCS#8 PEM. If the connectors workflow stores it in another
  form, convert it in the workflow step (never print it).

## Sequence

Every publish needs a sequence higher than the one installed apps hold (they refuse a lower one). The workflow reads
the published list's `sequence` and adds 1 (1 for the first publish).

## Owner checklist

1. Add `templates/`, `build-templates.mjs` (e.g. `scripts/`), `schema/template-v1.json` and the workflow steps to
   anchorsprint/ezychat-connectors; pin every action to a full commit SHA (org rule).
2. Allow the `templates/` path in the `dl.ezychat.ai` bucket (same credentials as `connectors/`).
3. First publish: sequence 1, the 18 templates at version 1 (no change in installed apps: equal versions keep the
   app's own copy). From then on a new template or a version 2 fix reaches every 0.1.75+ app without a release.
