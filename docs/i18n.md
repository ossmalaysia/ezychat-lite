# Languages (i18n)

EzyChat Lite ships in **English (`en`)**, **Bahasa Melayu (`ms`)** and **Simplified Chinese
(`zh-CN`)**. English is the source language and the fallback for any missing text.

## How the language is chosen

| Surface                   | Language source                                                                                             |
| ------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Web app (signed in)       | The member's saved choice (`users.locale`, set from Account menu → Language; follows them to every device). |
| Web app (before sign-in)  | This browser's last choice (`wati.locale` in local storage), else the browser languages, else English.     |
| Push notifications        | The recipient's saved choice (`users.locale`), else English.                                                |
| Desktop tray/dialogs/page | The operating-system language (`app.getPreferredSystemLanguages()`); it is per machine, not per member.    |

`resolveLocale()` in `packages/shared/src/i18n/locales.ts` maps browser/OS tags to a supported
language: `ms-MY` → `ms`; `zh`, `zh-Hans`, `zh-SG`, `zh-MY` → `zh-CN`. Traditional Chinese tags
(`zh-TW`, `zh-HK`, `zh-Hant`) fall through to English until a `zh-TW` catalog exists.

API error messages stay English on the wire (logs stay searchable). The web app translates them
in `errorMessage()` (`apps/web/src/api/client.ts`) by error code, or by exact message through
`KNOWN_SERVER_MESSAGES`; anything else is shown as sent.

## Where text lives

| Surface      | Catalogs                                                                | API                                                       |
| ------------ | ----------------------------------------------------------------------- | --------------------------------------------------------- |
| Web          | `apps/web/src/i18n/locales/<locale>/<namespace>.json`                   | `useTranslation('<namespace>')` (react-i18next), `<Trans>` |
| Server push  | `packages/server/src/i18n/messages.ts`                                  | `t(locale, 'push.newMessage')`                            |
| Desktop      | `apps/desktop/src/i18n.ts` (type-only shared import; see LEARNINGS)     | `t(locale, 'tray.open')`                                  |

Web namespaces: `common` (shared words, account menu, error boundary), `app` (app shell
components), `auth` (sign-in, password, setup), `inbox`, `admin`, `errors`. Only English is in the
main bundle; other languages load as separate chunks when selected (before first paint for a
saved choice).

Keys are typed from the English JSON: a typo in `t('...')` fails `npm run typecheck`.

## Adding a language

1. Add an entry to `SUPPORTED_LOCALES` in `packages/shared/src/i18n/locales.ts` (code, native
   name, English name, `intlTag` for date/number formatting). Add language-only fallbacks to
   `LANGUAGE_FALLBACK` if needed (e.g. `id: 'id'`).
2. Copy `apps/web/src/i18n/locales/en/` to `apps/web/src/i18n/locales/<code>/` and translate.
3. Map the date-fns locale in `apps/web/src/i18n/date-locale.ts`.
4. Add the catalog object to `packages/server/src/i18n/messages.ts` and `apps/desktop/src/i18n.ts`.
5. Run `npx vitest run apps/web/src/i18n packages/server/src/i18n apps/desktop/src/i18n.test.ts` —
   the catalog tests fail on missing/extra keys, empty values or placeholder mismatches.
6. Smoke every screen at phone width in the new language:
   `SMOKE_LOCALE=<code> node e2e/screens.smoke.mjs <url> <outDir>` and review the screenshots.
7. Have a native speaker review the strings before release.

## Writing rules

- No literal user-facing strings in feature code (ESLint `i18next/no-literal-string` guards JSX
  text and `aria-label`/`placeholder`/`title`/`alt`/`label`; toasts and constants need the same care).
- Never build sentences from translated fragments; use `{{placeholders}}` and `<Trans>` for
  embedded links or emphasis.
- Plurals: English needs `key_one` and `key_other`; Malay and Chinese only `key_other`.
- Keep product names (EzyChat Lite, WhatsApp, Cloudflare) and user content untranslated.
- Components that render `lib/format.ts` output must call `useTranslation()` so they re-render
  when the language changes.
- Malay text is often ~30% longer than English: keep labels short and check 360px layouts.
- Every change adds the key to **all** locales in the same PR (the catalog test enforces this).

The Malay and Chinese strings were drafted for the first release and still need native-speaker review.
